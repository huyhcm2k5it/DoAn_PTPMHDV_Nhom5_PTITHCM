# Diagnostic

Owner: Huy. Go/Echo/pgx with domain/application independent of infrastructure.

Implemented scope: DI-002–011 and the patient-owner path of DI-013. LAB_TECH can collect/reject/recollect, enter drafts and submit complete results; LAB_REVIEW can return results for rework or publish them after the two-person check. Published-result events contain identifiers and publication metadata only. Patient owners can read paginated PUBLISHED results with a current DI-013 lease. Staff detail remains separate from patient access. Every write requires a UUID Idempotency-Key; retries must use the same key and body. DI-001 is documented in OpenAPI as private and disabled by default; no public recovery POST is registered.

DI-012 is present but not operational in the PostgreSQL adapter: it requires an authoritative current doctor/visit grant projection, and the Appointment owner has not supplied that event/projection here. It also rejects any order whose charge or settlement is not confirmed paid; cancellation is only valid after successful settlement and before specimen collection. The endpoint fails closed with 503 until the grant integration exists. It never reports a refund as complete; the response remains `PENDING_SYNC` until Billing status is projected. Doctor reads of both DI-003 and DI-013 fail closed with 503 until a current revocable doctor/visit grant projection is available.

For the group demo, load Huy's `DIAGNOSTIC_DATABASE_URL` as `DATABASE_URL`: it must select `diagnostic_db` on Neon with `sslmode=require`. Run `go run ./cmd/migrate` before `go run ./cmd/api`. Configure LISTEN_ADDR, JWT_ISSUER, JWT_AUDIENCE and JWT_PUBLIC_KEY_FILE from the shared Identity key pair. JWT verification uses RS256 and the service's access projection; missing Identity configuration fails closed. Health readiness confirms schema, not external integration readiness.

Run `go run ./cmd/worker` with the same online DATABASE_URL and `RABBITMQ_URL` set to Quân's `UMC_AMQP_URL` (`amqps://`). DIAGNOSTIC_DECLARE_TOPOLOGY=1 declares only Diagnostic-owned exchanges/queues and binds to already provisioned source exchanges. Shared topology remains the infrastructure owner's responsibility. Worker uses manual ACK, durable retry/dead-letter storage, mandatory publisher confirmations and transactional outbox. A process crash after publish may redeliver; the transaction inbox and requestId guard prevent repeated business effects.

CreateLabOrder is accepted only from Clinical command exchange and expected routing key. Canonical requestHash is SHA256 of the Go JSON map containing requestId,visitId,patientId,doctorId,testSnapshot,authorizedAt (sorted map keys). Unit/referenceRange are included even when empty. One clinical request creates one order, one charge request and LabOrderResolved atomically. Price data comes from the local Catalog projection at authorizedAt. Catalog sequence gaps or checkpoints older than30seconds block new charges. Unavailable projections remain retryable; they do not fabricate payment or an accepted order.

The trusted bootstrap command `go run ./cmd/import-projections` reads JSON array from stdin. Each entry has kind,key,value,version. Kinds: access,patient,TEST,DOCTOR,LAB_PRICE,catalog. Entity keys are UUIDs; catalog key is checkpoint. Access value is `{userId,actorType,status,tokenVersion,capabilities}`. Patient value is `{ownerUserId,active}`. DOCTOR value is `{identityUserId}`. TEST value contains id,code,name,unit,referenceRange,revision,status. LAB_PRICE value contains itemId,itemType=LAB,priceVersionId,revision,amountVnd,effectiveFrom,effectiveTo?. Catalog checkpoint contains sequence,at. This operator tool is not exposed as an HTTP endpoint; imports require increasing versions and reject conflicting same-version content. CatalogChanged and access messages subsequently update the normal projections.

Collection requires local ChargePrepared and a matching successful settlement fence from trusted Billing messages. FAILED decisions leave a tombstone even before reserve. UNKNOWN and timeouts keep the lock. The worker emits QuerySettlement every30seconds for locked orders. Reject keeps specimen history and audit identity; recollect creates a new specimen/sequence/barcode on the same order and never requests a new charge. Barcodes remain unique after rejection. Result drafts, review, publication and owner reads use immutable order-test snapshots and do not leak result values to Clinical.

Verification: `go test ./...`, `go vet ./...`, `go build ./...`; on Windows run `python tools/huy/test_diagnostic_postgres.py` for the isolated PostgreSQL HTTP/lifecycle suite and actual OpenAPI response fixtures. The Diagnostic integration writes the real `LabResultPublished` envelope; `python tools/huy/test_clinical_postgres.py` consumes it through Clinical's receiver when that fixture exists. Broker tests use `-tags=brokerintegration` and an isolated TEST_RABBITMQ_URL. CI validates both result-response fixtures against the OpenAPI contract and runs the cross-service wire test.

Integration boundary: current repository's Catalog full entity/checkpoint publisher and live Identity/Billing handoffs must be available for a full team journey. Trusted bootstrap supports local verification but is not evidence of the complete group Gate3. No HTTP calls to Billing or cross-service database access are used.
